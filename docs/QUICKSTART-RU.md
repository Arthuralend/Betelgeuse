# Betelgeuse 0.8.0: быстрый старт

## Телефоны

1. Установите новую сборку поверх 0.7.1, сохраняя данные и ключи.
2. Откройте P2P, задайте имя, нажмите «Сохранить имя». Ядро заводится
   автоматически. Дождитесь статуса «Интернет P2P готов».
3. Включите «Устройства рядом», откройте P2P на другом телефоне. На iOS
   разрешите локальную сеть; Android использует системный DNS-SD.
4. В разделе «Рядом» нажмите «Добавить» напротив найденного человека.
   Он должен принять запрос. Проверьте короткий хвост Peer ID на обоих телефонах.
5. Откройте контакт, отправьте сообщение, файл или начните звонок.

На одной Wi-Fi сети обнаружение iOS/Android происходит по DNS-SD.
На двух Apple-устройствах также доступен MultipeerConnectivity,
позволяющий обменяться подписанными профилями поблизости (транспорт
выбирает iOS). Это не универсальный Bluetooth между iOS и Android.
Обнаружение работает в foreground; доступ к контактам требует согласия.
Публичные имена и Peer ID видны находящимся рядом устройствам при включённом
поиске. Приватные ключи, история и файлы не пересылаются при знакомстве.

## Интернет

Подготовленные для владельца проекта установочные пакеты могут получить
преднастроенный доверенный bootstrap-узел. Общедоступные unsigned сборки
GitHub не содержат персональной конфигурации. Дополнительный узел можно
ввести при необходимости в «Дополнительные настройки»: полный numeric-IP
multiaddr с TCP портом и проверяемым Peer ID. Поддерживается до восьми
доверенных маршрутов в общей конфигурации.

Приложение само подключается, резервирует relay, публикует подписанные
записи и обновляет маршруты контактов. Доверенные адреса и контакты
сохраняются в локальной базе/настройках. При смене доступной сети
происходит переподключение. IP узла не выводится в обычном интерфейсе,
но технически виден в сетевых соединениях. Не включайте пароли в
конфигурацию.

Через разные сети: оба телефона должны быть запущены и иметь доступ к
узлу. Если медиа не соединяется при работающих сообщениях/файлах,
проверьте свой STUN/TURN в WebRTC. Relay libp2p не является TURN.

## Развёртывание собственного узла

Подходит уже работающий Betelgeuse 0.7.0 relay, при соблюдении
совместимого протокола 1.x. На собственном сервере используйте
выданный CLI и выделенный порт; при запуске следует объявить внешний
адрес узла. Доступность внешнего TCP порта проверяется отдельно.
В 0.8.0 новая команда `configure_network` принимает settings:
`{"enabled":true,"name":"Alice","addresses":["<полный multiaddr>"]}`.
Настройки сохраняются. Для сборки без ручного ввода можно передать
`BETELGEUSE_BOOTSTRAP_CONFIG=/path/to/bootstrap-local.json` с JSON
`{"nodes":["<полный multiaddr>"]}`. Для iOS этот файл копируется в
bundle, для Android в assets. Не добавляйте реальные адреса в публичный
репозиторий без разрешения оператора.

## Проверка

- LAN: 2 телефона, iOS/Android, взаимное добавление; отказ не создаёт контакт.
- Apple рядом: 2 iPhone, согласие на обмен P2P-профилями и тест старого вызова.
- Интернет: разные сети, отключение Wi-Fi, проверка авто-переподключения.
- Файлы: 2 МиБ, 20 МиБ, проверка содержимого, пауза и возобновление.
- WebRTC: два направления, голос/видео, камера/микрофон, затем TURN при необходимости.
- Проверка 0.8.0 на физическом iPhone 11 Pro/iOS 18.5 необходима: код
  исправляет потенциально несовместимый PCM формат и сериализует аудиособытия,
  но отсутствие вылета подтверждается только устройством.

Нет фоновых входящих звонков, push или офлайн-файлов. Не удаляйте
данные приложения при обновлении. Старые режимы оставлены совместимыми.
