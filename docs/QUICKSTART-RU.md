# Проверка Betelgeuse 0.7.0

## Один Wi-Fi

1. Установите обе мобильные сборки. На iPhone откройте P2P, на Android —
   новый основной экран. Разрешите доступ к локальной сети на iPhone.
2. На каждом телефоне задайте имя, дождитесь запуска Rust-ядра и создайте
   приглашение. Обменяйтесь приглашениями и добавьте контакты на обоих.
3. Откройте контакт и отправьте текст. Отмеченное доставленным сообщение
   имеет подтверждение от получателя.

## Разные сети

Для первой проверки используйте доступный Linux VPS либо компьютер с
доступным внешним TCP-портом 4001. GitHub Actions только собирает бинарники.
Постоянный узел можно запускать на любом принадлежащем участнику компьютере.

Из Linux CLI-артефакта:

```sh
chmod +x betelgeuse
./betelgeuse --data-dir ./relay-data account create
./betelgeuse --data-dir ./relay-data node start --server --relay-server \
  --listen /ip4/0.0.0.0/tcp/4001
```

Процесс ожидает JSON-команды в терминале. Для длительной работы оставьте
его в открытой SSH-сессии или в tmux. После события started введите:

```json
{"op":"announce","address":"/ip4/ПУБЛИЧНЫЙ_IP/tcp/4001"}
```

Замените ПУБЛИЧНЫЙ_IP настоящим адресом узла. Сформируйте полный multiaddr:

```text
/ip4/ПУБЛИЧНЫЙ_IP/tcp/4001/p2p/PEER_ID_УЗЛА
```

Откройте входящий TCP порт 4001 для этого узла в сетевых настройках.
На обоих телефонах:

1. Вставьте полный multiaddr в поле «Адрес узла /p2p/…».
2. Нажмите «Подключить узел», затем «Резервировать relay».
3. Дождитесь сообщения о доступности ретранслятора.
4. Нажмите «Опубликовать профиль и маршруты», затем «Создать приглашение».
5. Обменяйтесь приглашениями. Откройте контакт и отправьте сообщение.
6. Для поиска профильной записи используйте Peer ID в поле DHT.
7. Выберите контакт и отправьте небольшой файл. Получатель нажимает
   «Принять». Проверьте, что файл можно сохранить/открыть, отправитель
   получил подтверждение. Повторите с файлом 20–50 МиБ и паузой/возобновлением.
8. Проверьте голосовой и видеозвонок в обе стороны, кнопки микрофона и камеры,
   отказ от звонка и завершение. Разрешите камеру/микрофон только в момент
   принятого звонка. Оба приложения должны быть открыты.
9. Если текст и файл работают, а медиа не соединяется, откройте настройки
   ICE и введите адрес своего STUN/TURN. Для сложных NAT/CGNAT нужен TURN
   (URL вида turn:host:3478, логин и пароль). libp2p relay не является TURN.
   Проверьте звонок без TURN, затем с TURN. Не публикуйте пароль в GitHub.

Доступный маршрут через узел необходим, когда прямое соединение через
NAT недоступно. Протокол DCUtR пытается обновить соединение до прямого
при технической возможности. Оба приложения должны быть активны.

## Важные особенности этой беты

- Профильные и маршрутные записи имеют срок действия. Публикацию можно
  обновить из приложения. Автоматическая периодическая публикация пока
  не реализована.
- Подписанные приглашения публичны в пределах указанного маршрута;
  передавайте их выбранным контактам.
- Формат идентичности и протокол 0.3.0 отличаются. Прежние локальные
  данные остаются в отдельном режиме совместимости; новый профиль нужно
  создать и подтвердить новым приглашением.
- В новом режиме доступны звонки WebRTC и файлы до 256 МиБ.
  Перед получением файла требуется согласие; хеш SHA-256 проверяется.
  Возобновление работает в пределах текущего запуска. После отключения
  сети повторите команду возобновления; после перезапуска нужен новый обмен.
- Нет обязательного сервера разработчика. Для начального подключения
  на разных сетях нужен доступный узел, медиа может потребовать TURN.
- Нет фоновых входящих звонков, push-уведомлений или офлайн-доставки файлов.
- Протокол проверен в CI на процессах, но связь двух физических телефонов
  через разные операторы пока не подтверждена.

## Матрица полевого теста

| Сценарий | Проверить |
|---|---|
| iPhone Wi-Fi, Android LTE/5G | Текст, файл, звук и видео |
| iPhone LTE/5G, Android другого оператора | Звук, видео, файл, входящий и исходящий звонки |
| Два оператора с CGNAT | Без TURN, затем с собственным TURN |
| Временно отключить сеть | Завершение звонка, восстановление соединения, возобновление файла |

Фиксируйте модель устройства, ОС, оператора, время, результат и используемый маршрут; не передавайте частные ключи или TURN-пароли.
